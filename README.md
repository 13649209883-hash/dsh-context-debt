# dsh-context-debt · 上下文债务表

> 面向使用billion-context等压缩上下文工具，但对会话任务精度有要求的人群

## 内容

会话压缩可能导致这样一个现象：**当前占用看起来很健康，但会话的记忆已经全是压缩摘要了。**

压缩类插件会压缩实际上下文大小，使得使用者无法通过DSH自带的仪表盘，查看当前会话健康程度(压缩程度)

本插件旨在提供真实的上下文量，并根据本机过往样本推测出最佳上下文长度。

极低性能开销，几乎不会增加额外的token消耗。

组合压缩类插件使用，可扩展单会话上下文达到10M量级且模型能力不会过分下降。

## 30 秒上手

**1. 让 profile 能解析到插件目录**（在 profile 目录里执行）：

```bash
pnpm add link:/path/to/dsh-context-debt
```

**2. 在 profile 的 `cordis.patch.yml` 里加一条**：

```yaml
- insert:
    - id: context-debt
      name: dsh-context-debt
      config:
        warnPercent: 200
        dangerPercent: 350
```

**3. 重启 DSH。** 往系统临时目录的 `dsh-context-debt.boot.log` 里会多一行 `loaded pid=… kSource=…`，用它确认真的加载了。

之后对话里会多出一行（每个会话第一轮一次，跨档时升级成完整告警）：

```
【上下文】119% 偏大 · 日志 1.70MB · 原始 1.21M · 压缩后 0.08M · 14.4×
```

各项含义见下面「三个数」一节。token 一律用百万（M）为单位，跟窗口同一个量纲，两个数能直接比大小。没有实测解码时最后一个数会缺，并标注「（估算）」。

不想让插件往对话里插字，就直接看面板——不消耗 token：

```bash
node panel.mjs              # 一张快照表（前 12 个，按债务降序）
node panel.mjs --watch 5    # 每 5 秒刷新（终端）
node panel.mjs --serve      # 起网页看板 http://127.0.0.1:7788/（每 5 秒自动刷新）
node panel.mjs --anon       # 会话 id 换成稳定别名（分享截图用）
```

```

--------------------------------------------------------------------------
3f9a71c2    7.79MB    4.95M    0.13M    37.7×   472%     危险    46m 前
```

## 装完不说话怎么查

这个插件在没找到会话日志时**静默跳过**（设计如此：绝不打扰对话）。所以「装上了但一句提示都没有」有两种可能，先看 `dsh-context-debt.boot.log`（在系统临时目录里）：

| 日志里出现 | 说明 |
|:--|:--|
| `loaded pid=… kSource=…` | 插件被加载了（只有这一行代表「装上了」） |
| `no-log session=… step=…` | 加载了，但没找到那条会话的日志文件 |
| `report session=… 156% 偏大 -> "…"` | 真正注入了简报 |

如果日志里出现 `no-log`，说明会话日志不在默认位置（`~/.dsh/sessions/<workspace>/session-<id>/session.v4.jsonl.zstd`）——自定义安装目录或 DSH 换了布局时需要改 `sessionsRoot()`。

### 注意事项（安装环境）

下面四条，装的时候大概率会碰上其中一两条。它们**不是 bug**——代码按设计工作，只是环境或用法上有前提：

1. **只建了软链接不够**。profile 的 `package.json` 里必须有依赖行（`pnpm add link:…` 或手改），只在 `node_modules` 里放个 junction 会在启动时报 `no loader entry matched`。
2. **`pnpm add link:` 可能被卡住**（联网校验/供应链策略）。可以手改 `package.json` 的 `dependencies` 加一行 `"dsh-context-debt": "link:E:/path/to/dsh-context-debt"`，再让 `node_modules/dsh-context-debt` 指过去。
3. **Windows 路径用正斜杠**：`link:E:/deepseek/plugins/dsh-context-debt`。反斜杠在 YAML/JSON 里会被转义，链接会解析成怪路径。
4. **服务端插件没有热重载**。改完代码必须重启 DSH，界面刷新没用。

### 已知缺陷（0.1.0，已修）

> 0.1.0 找不到会话日志，永远不说话。原因：DSH 的 `session.id` 自带 `session-` 前缀，旧代码又包了一层，拼成 `session-session-…`，于是**每一台 DSH 上都会静默失效**。

这不是「偶尔不灵」，而是稳定失效——100% 复现，和你的环境无关。**如果你装的是 0.1.0，别怀疑环境，就是这个**，升级到 0.1.1 即可（两种 id 写法都认，并加了上面那三行诊断日志）。

判据很简单：**照文档做也做不到，是缺陷；不照文档做才做不到，是注意事项。**

## 你现在在哪一档

| 档位 | 债务 / 窗口 | 意味着什么 | 该做什么 |
|:--|:--|:--|:--|
| 正常 | < 100% | 还没被压缩过，或刚压过一轮 | 照常用 |
| 偏大 | 100% ~ 200% | 已压掉不足一份完整上下文 | 可以继续，但别在这条会话里开新的大任务 |
| 警戒 | 200% ~ 350% | 记忆已主要是摘要，细节开始找不回来 | 把当前任务收尾，之后换新会话 |
| 危险 | ≥ 350% | 摘要的摘要，回答开始「编」而不是「回忆」 | 立刻换会话，只把结论带过去 |

四档互不重叠，边界就是第二列的区间，阈值可在配置里改。判断时只需要看**自己在哪一档**，不必纠结精确数字。

## 三个数：原始 / 压缩后 / 倍率

对话里报的是「原始」这一类估算；命令行和面板会真的解一次会话日志，给出三个数：

| 数 | 含义 | 怎么来的 |
|:--|:--|:--|
| 原始 | 会话里累计写进去的原文 | message + tool 事件的 JSON 长度，4 字符 ≈ 1 token（**上界**） |
| 压缩后 | 最近一次真正发出去的 prompt 规模 | 日志里的上游 `usage.totalTokens`（**实报**） |
| 倍率 | 原始 ÷ 压缩后 | — |

三个 token 数（原始、压缩后、窗口）**一律以百万（M）为单位**，因为窗口就是 1M 上下，同一量纲才能一眼比出「累计是窗口的几倍、这一发用了窗口的几成」。日志体积单独用 MB（那是磁盘上压缩文件的字节数，不是 token）。

倍率最直白：**20× 意味着你看到的上下文里，每 20 个 token 只有 1 个来自原文**，其余都是摘要。

解码结果按「文件 + 修改时间 + 大小」缓存，`--watch` 不会反复解同一个文件；要纯 stat 的速度就加 `--fast`，代价是没有后两列。

## 开销：一次 stat，外加节流的解码

```
债务 ≈ 会话日志体积 × k        k 默认 0.71，可用本机数据校准（见下）
```

每轮开始**必做**的只有一次 `fs.stat`（O(1)，毫秒级），用它算百分比和档位。

「原始 / 压缩后 / 倍率」这三个数需要解码会话日志。解一份 8MB 的日志约 200ms，每轮都解会明显拖慢响应，所以 `lib/real.mjs` 做了节流：

- 同一个文件 **60 秒内不重复解**；
- **硬下限 15 秒**——文件涨得再快也不会每轮都解；
- 文件比上次解码时长大了 25%（且至少 1MB）才提前重解；
- 中间那些轮次沿用上一次的结果，数字滞后一两轮；实在没有实测时那一行会标「（估算）」。

CLI 和面板是你主动跑的时候才解码，不受这个限制。

## k：跟着你本机数据走

出厂 0.71 是几个样本的中位数，不是定律。用本机会话自己标定：

```bash
node calibrate.mjs          # 看最近几个会话的实测 k（不写盘）
node calibrate.mjs --n 12   # 多看几个
node calibrate.mjs --write  # 写 data/calibration.local.json，插件下次启动生效
node calibrate.mjs --show   # 看当前生效的 k、来源、样本档位
```

做法：把最近几个够大的会话逐帧解出来，算「原始 token ÷ 日志字节」，取中位数。图多/二进制多的会话 k 明显偏低（< 0.25），单独标出、不进中位数。

**要几个样本才算数**——少于 3 个不下结论：

| 计入样本数 | 档位 | 插件怎么办 |
|:--|:--|:--|
| 0–2 | 不足 | 不采用，继续用出厂 0.71（`kSource` 里写「需 ≥3」） |
| 3–4 | 初步 | 采用，但数值可能再跳 20% |
| 5–9 | 可用 | 采用，日常够用 |
| ≥10 | 较稳 | 采用，可以当结论 |

为什么是这几个数：纯代码会话 k 偏低（0.3~0.4），中文长对话偏高（0.7~0.8）。3 个样本容易同质；5 个能混进一点差异；到 10 个时中位数的抖动已小于档位宽度。所以**攒到 5 个再 `--write`，10 个以上最放心**；样本不足时 `--write` 会拒绝写出（退出码 2）。

优先级：**配置里的 `k` > 本地标定文件 > 出厂 0.71**。启动日志的 `kSource` 一眼看出用的哪个，形如 `local/10样本/较稳`。

本机实测：10 个文本会话，k 中位数 **0.662**（区间 0.326 ~ 0.782），另剔 2 个偏图文样本。同一个 7.79 MB 会话，按出厂 0.71 算 553%，按 0.662 算 515%——出厂值对纯文本略保守。

三条必须说清的：

1. **k 不是常数**。它取决于中英文/代码比例、事件构成、压缩粒度，本机 10 个样本跨度就有 2.4 倍。
2. **它不是计费数字**。要精确 token 请读上游 `usage`；k 只用来判断「在哪一档」。
3. **它不需要靠别人替你标**。`calibrate.mjs` 在你自己的机器上扫自己的日志就能算，插件读本地文件——**这个项目不依赖社区提交数据做后续维护**。`data/calibration.json` 只是出厂那几行样本的留档（匿名），不填不影响功能。

## 越过危险线之后会怎样

不是模糊的「感觉它不行了」，而是一组可辨认的症状，集中出现在会话后半段、尤其是你**在这种会话里新开一个长任务**之后：

1. **无视既定规则**——项目说明里写死的约束开始被跳过，而且模型不觉得自己违反了。
2. **改代码反复出错**——同一个错误改三四次还在，越改越大，最后把原本能跑的部分改坏。
3. **不查记忆**——该翻文档/知识库的时候凭印象答，或只扫一眼就下结论。
4. **会话内记忆偏差**——把前面说过的话记错、张冠李戴，把「计划」当成「已完成」。
5. **幻觉**——声称跑过某个命令、改过某个文件（其实没有），或直接给出想象出来的输出、行号。

第 5 条最危险：它不「答错」，它**伪造证据**。出现它基本等于这条会话的细节层已不可信。按严重度：第 5 条出现就换会话；第 2、3 条出现该收尾；第 1、4 条是更早的信号。

这条路也不是慢慢变笨的线性过程，有两级台阶：

1. **摘要化**（200% 之后）：信息变薄，还能答，但开始漂。
2. **撞硬上限**（接近窗口）：请求直接被上游拒绝。它**不提前通知**，表现往往不是报错，而是**那一轮没有回应**——消息发出去、你等它想，其实请求根本没被接受。

本插件不做截断、不改请求，只在第一级喊停。真正的保险丝要由压缩插件提供：billion-context 从 0.1.203 起才有「超窗保险丝 + 超限请求不再裸发」，0.1.202 及更早会把超限请求原样发出去。**两个一起用才是完整防线**——本插件管「该不该继续」，压缩插件管「这一发会不会被拒」。

## 分界线从哪来

不是拍脑袋，是从 4 个真实会话标定出来的（债务按日志逐条解码校准，样本匿名）：

| 样本 | 日志体积 | 实际堆积 | 反推 k | 结局 |
|:--|:--|:--|:--|:--|
| A | 7.79 MB | 4.95M tokens（472%） | 0.635 | 连续三次空回复，最后只能换会话重做 |
| B | 7.62 MB | 5.70M tokens（543%） | 0.748 | 长任务后半段开始跑偏，返工重来 |
| C | 6.86 MB | 5.87M tokens（587%） | 0.855 | 压缩比 69×，回答基本靠摘要，细节问不出来 |
| D | 1.16 MB | 0.71M tokens（68%） | 0.615 | 正常结束，没有异常 |

取中位数 **k = 0.71**，样本间误差约 ±20%。结论很朴素：**越过 200% 之后，任务成功率的下降用户自己就能察觉；到 350% 基本只剩换会话一条路。** 这是可配置的起点，不是定律。

## 配置

| 键 | 默认 | 说明 |
|:--|:--|:--|
| `enabled` | `true` | 总开关 |
| `warnPercent` | `200` | 越过「警戒」档的阈值 |
| `dangerPercent` | `350` | 越过「危险」档的阈值 |
| `window` | `1048576` | 拿不到模型窗口时按这个算 |
| `k` | `null` | tok/byte 标定值；`null` = 用本地标定（需 ≥3 个样本），否则出厂 0.71 |
| `report` | `'session'` | 报告节奏，见下 |

`report` 三档：

| 值 | 行为 | 上下文成本 |
|:--|:--|:--|
| `session`（默认） | 每个会话第一轮报一行简报，跨档时给完整告警 | 每会话约 30 字 |
| `always` | 每轮都报一行简报，跨档时给完整告警 | 每轮约 30 字 |
| `warn` | 平时完全静默，只在跨档时告警 | 几乎为零 |

行为约束（有意为之）：

- **每轮只在第一步判断**，每轮最多一条提示；
- **同一档位只提醒一次**，债务继续涨才升级措辞，不刷屏；
- 任何异常都被吞掉，绝不影响正常对话。

## CLI

```bash
node cli.mjs                 # 最近改动的会话
node cli.mjs --all           # 全部，按债务降序
node cli.mjs --kw <会话id>   # 指定会话
node cli.mjs --top 10        # 近 7 天最重的 10 个
node cli.mjs --json          # 机器可读
node cli.mjs --fast          # 不解码，只给估算
node cli.mjs --anon          # 会话 id 换成稳定别名
```

```
[context-debt] 3f9a71c2  日志 7.79MB  原始 4.95M  压缩后 0.13M  37.7×  472% 危险
```

退出码：有会话越过 `warnPercent` 时为 1，方便挂到脚本里。

## 网页看板

```bash
node panel.mjs --serve        # http://127.0.0.1:7788/
node panel.mjs --serve 7799   # 端口被占就换一个
```

一张表，每 5 秒自动刷新（页内 `fetch`，不重载）：会话、日志体积、原始、压缩后、倍率、占窗口、档位、最后改动；底部一行「最重 X 563% 危险」。

它和终端版读的是同一份数据、同一个 `k`。数据只在本机内存里，页面不带任何外部请求，关掉进程就没了。适合折叠窗口里挂一个，或者丢到第二个屏。

> 顺带一个不花 token 的用法：让助手在每轮回复末尾复述一行 `【上下文】…`（插件注入的那句），你就不用切窗口也能看出趋势——但那是助手侧的约定，不是这个插件的能力。

## 局限

- 只认 DSH 的会话日志布局（`~/.dsh/sessions/*/session-<id>/session.v4.jsonl.zstd`），别的客户端要改 `sessionsRoot()`；
- 「原始」是 4 字符 ≈ 1 token 换出的**上界**（CJK 高估、代码偏低），「压缩后」是上游 `usage` 实报；
- 插件在对话里报的是「字节 × k」估算（±20%），精确数字看 CLI / 面板；
- 依赖日志追加写入的形态；
- 它不压缩、不改变任何上下文，只测量与提示；
- 分界线来自小样本（4 个会话、单机），换成你自己的 `calibrate.mjs` 结果更贴。
