# dsh-context-debt · 上下文债务表

> 压缩插件告诉你「这一发会不会超窗」，这个插件告诉你「这个会话已经被压到什么程度、还值不值得继续」。

长会话有一种失败没人提示：**当前占用很健康，但会话的记忆已经全是压缩摘要了。**

压缩类插件（billion-context、DSH 原生压缩等）都以「当前占用」为指标——压一次，占用就掉回去，于是提醒永远停在「正常」。可用户真正感受到的「模型变笨了」来自另一件事：这个会话累计吃掉了几份完整上下文、被压缩过多少代、关键细节还是原文还是二手摘要。

这类插件按设计不回答这个问题（它们的目标是让长会话能继续），所以用户在长任务里压缩时，**不知道自己压缩到什么程度才会开始不能接受**。

本插件补这一格：每轮开始时给出一个**累积债务**估计，越过阈值就提醒一次，并给出有实测依据的分界线。

## 「变笨」到底指什么

不是模糊的「感觉它不行了」，而是一组**可辨认的症状**，集中出现在会话后半段，尤其是你在这种会话里**新开一个长任务**之后：

1. **无视既定规则**——项目说明里写死的约束开始被跳过，而且模型不觉得自己违反了。
2. **改代码反复出错**——同一个错误改三四次还在，越改越大，最后把原本能跑的部分改坏。
3. **不查记忆**——该翻文档/知识库的时候凭印象答，或只扫一眼就下结论。
4. **会话内记忆偏差**——把自己前面说过的话记错、张冠李戴，把「计划」当成「已完成」。
5. **幻觉**——声称跑过某个命令、改过某个文件（其实没有），或直接给出想象出来的输出、结果、行号。

第 5 条最危险：它不需要「答错」，它会**伪造证据**，让人以为事情做完了。出现它基本等于这个会话的细节层已经不可信。

这五条按危险程度排：第 5 条出现就换会话；第 2、3 条出现就该收尾；第 1、4 条是更早的信号。


## 指标

```
债务 ≈ 会话日志体积 × k        k 默认 0.71（估算值，见「k 只是一个估算」）
```

只看会话日志文件的大小，**不解码、不解析、不读内容**——一次 `fs.stat`，O(1)，毫秒级，几乎零开销。

## 档位

| 档位 | 债务 / 窗口 | 意味着什么 | 该做什么 |
|:--|:--|:--|:--|
| 正常 | < 100% | 还没被压缩过，或刚压过一轮 | 照常用 |
| 偏大 | 100% ~ 200% | 已压掉不足一份完整上下文 | 可以继续，但别在这条会话里开新的大任务 |
| 警戒 | 200% ~ 350% | 记忆已主要是摘要，细节开始找不回来 | 把当前任务收尾，之后换新会话 |
| 危险 | ≥ 350% | 摘要的摘要，回答开始「编」而不是「回忆」 | 立刻换会话，只把结论带过去 |

四档互不重叠，边界就是第二列的区间。默认值可在「配置」里改。

判断时只需要看**自己在哪一档**，不必纠结精确数字。

## 分界线从哪来

不是拍脑袋，是从 4 个真实会话标定出来的（债务按会话日志逐条解码校准，样本匿名）：

| 样本 | 日志体积 | 实际堆积 | 反推 k | 结局 |
|:--|:--|:--|:--|:--|
| A | 7.79 MB | 4.95M tokens（472%） | 0.635 | 连续三次空回复，最后只能换会话重做 |
| B | 7.62 MB | 5.70M tokens（543%） | 0.748 | 长任务后半段开始跑偏，返工重来 |
| C | 6.86 MB | 5.87M tokens（587%） | 0.855 | 压缩比 69×，回答基本靠摘要，细节问不出来 |
| D | 1.16 MB | 0.71M tokens（68%） | 0.615 | 正常结束，没有异常 |

取中位数 **k = 0.71**，样本间误差约 ±20%。

结论很朴素：**越过 200% 之后，任务成功率的下降用户自己就能察觉；到 350% 基本只剩换会话一条路。** 这是可配置的起点，不是定律。

## k 只是一个估算

必须说清楚三件事：

1. **k 不是常数**。它取决于日志里中英文/代码的比例、事件类型构成、以及压缩插件写摘要的粒度。上面 4 个样本的 k 从 0.615 到 0.855，跨度就有 40%。
2. **它不是计费数字**。要精确 token 请读上游 `usage`；k 的用途是判断「在哪一档」，不是报账。
3. **它应该被更多数据修正**。目前只有 4 个样本，还是同一台机器、同一种用法。你在别的机器、别的语言、别的压缩插件下测出的 k 可能不同，而这种差异恰恰是这套阈值最需要的信息。

所以：**欢迎任何人用自己的压缩插件和环境跑一组数据，把 k 提交回来。** 仓库里的 [`data/calibration.json`](data/calibration.json) 就是收集这些行的表格——照着加一行，提 PR 或开 issue 贴 JSON 都行。

怎么量自己的 k：

1. 解一次会话日志，得到「实际堆积 tokens」（多数压缩插件留有日志/统计；也可按 message 与 tool 事件的 JSON 长度换算上界）；
2. 读上游响应里的 `usage`（`totalTokens`），那是「实际发出去」的量；
3. `k = 实际堆积 tokens ÷ 日志文件字节数`；
4. 把这一行填进 `data/calibration.json`，注明模型、压缩插件及版本。

## 安装（DSH）

1. 让插件目录能被 profile 的 `node_modules` 解析到，例如在 profile 目录里：

   ```bash
   pnpm add link:/path/to/dsh-context-debt
   ```

2. 在 profile 的 `cordis.patch.yml` 里加一条：

   ```yaml
   - insert:
       - id: context-debt
         name: dsh-context-debt
         config:
           warnPercent: 200
           dangerPercent: 350
   ```

3. 重启 DSH。启动后插件会往系统临时目录的 `dsh-context-debt.boot.log` 追加一行 `loaded pid=…`，用它确认真的加载了。

## 配置

| 键 | 默认 | 说明 |
|:--|:--|:--|
| `enabled` | `true` | 总开关 |
| `warnPercent` | `200` | 越过「警戒」档的阈值 |
| `dangerPercent` | `350` | 越过「危险」档的阈值 |
| `window` | `1048576` | 拿不到模型窗口时按这个算 |
| `k` | `0.71` | tok/byte 标定值 |
| `report` | `'session'` | 报告节奏，见下 |

`report` 三档：

| 值 | 行为 | 上下文成本 |
|:--|:--|:--|
| `session`（默认） | 每个会话第一轮报一行简报，跨档时给完整告警 | 每会话约 30 字 |
| `always` | 每轮都报一行简报，跨档时给完整告警 | 每轮约 30 字 |
| `warn` | 平时完全静默，只在跨档时告警 | 几乎为零 |

简报长这样（一行）：

```
【上下文】119% 偏大 · 已压 0.2 份 · 日志 1.7MB
```

行为约束（有意为之）：

- **每轮只在第一步判断**，每轮最多一条提示；
- **同一档位只提醒一次**，债务继续涨才升级措辞，不刷屏；
- 任何异常都被吞掉，绝不影响正常对话。

## CLI

```bash
node cli.mjs                 # 最近改动的会话
node cli.mjs --all           # 全部，按债务降序
node cli.mjs --kw <会话id>   # 指定会话
node cli.mjs --top 10        # 近 7 天最重的 10 个
node cli.mjs --json          # 机器可读，便于批量算 k
```

退出码：有会话越过 `warnPercent` 时为 1，方便挂到脚本里。

## 面板

不想让插件往对话里插字，就用面板看——它不产生任何 token 消耗：

```bash
node panel.mjs              # 一张快照表（前 12 个，按债务降序）
node panel.mjs --all        # 全部会话
node panel.mjs --watch 5    # 每 5 秒刷新
```

```
会话        日志      堆积      占窗口    档位    最后改动
--------------------------------------------------------------
3f9a71c2    7.90MB    5.80M     553%      危险    46m 前
c04be1d8    6.20MB    4.61M     440%      危险    20d 前
7ad2e390    4.70MB    3.49M     333%      警戒    20h 前
```

会话 id 是 8 位短标识，输出时会按债务降序，档位那一列带颜色。

## 局限

- 只认 DSH 的会话日志布局（`~/.dsh/sessions/*/session-<id>/session.v4.jsonl.zstd`）；
- 估算是近似值（±20%），不是上游 usage；
- 依赖日志为追加写入的形态；别的客户端需要改 `sessionsRoot()`；
- 它不压缩、不改变任何上下文，只测量与提示；
- 分界线来自小样本（4 个会话、单机），样本越多越准。

## 贡献

最需要的是**校准数据**，其次是新的会话日志布局适配。格式见 [`data/calibration.json`](data/calibration.json)。
